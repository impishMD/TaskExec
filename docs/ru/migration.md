# Миграция на TaskExec

[English](../en/migration.md) | **Русский**

## Существующая установка JEH

При переносе установки JEH используйте следующие имена компонентов TaskExec.
Сохраните базу данных и ключи шифрования.

| Было | Стало |
| --- | --- |
| Бинарник, служба и системный пользователь `jeh` | `taskexec` |
| Переменные `JEH_*` | `TASKEXEC_*` |
| Проект и сервис Compose `jeh` | `taskexec` |
| Тома `jeh_jeh-config`, `jeh_jeh-data` | `taskexec_taskexec-config`, `taskexec_taskexec-data` |
| `/etc/jeh`, `/var/lib/jeh`, `/tmp/jeh`, `/opt/jeh`, `/home/jeh` | Соответствующие пути `/…/taskexec` |
| Ansible `jeh_vars` и окружение задач `JEH_*` | `taskexec_vars` и `TASKEXEC_*` |
| Метрики `jeh_*` | `taskexec_*` |
| Go-модуль `github.com/impishMD/jeh` | `github.com/impishMD/taskexec` |
| Образ `impishmd/jeh` | Локальный `taskexec:dev`; релизные `impishmd/taskexec` / `ghcr.io/impishmd/taskexec` |

1. Соберите образ: `docker compose -f compose.yaml -f compose.dev.yaml build taskexec`.
2. Остановите старую службу и сохраните тома данных/конфигурации и `.env`.
   Копию SQLite делайте при остановленной службе.
3. Переименуйте ключи `.env` в `TASKEXEC_*`, сохранив значения, особенно
   `TASKEXEC_ACCESS_KEY_ENCRYPTION`. Сохраните учётные данные и имя существующей БД:
   новое имя по умолчанию `taskexec` не должно создать другую пустую базу.
4. Скопируйте оба тома под новыми именами с сохранением владельца (UID 1001 в контейнере).
   Не выполняйте `down -v` и не удаляйте старые тома. Пустые новые тома создадут отдельную
   установку без прежних пользователей и проектов.
5. В копии конфигурации замените абсолютные пути `/…/jeh` на соответствующие
   `/…/taskexec`. Сохраните ключи cookie, шифрования и остальные параметры.
   Для SQLite поле `sqlite.host` должно указывать на скопированную базу.
6. Выполните `docker compose -f compose.yaml -f compose.dev.yaml up -d --no-build`.
   Войдите заново: cookie авторизации называется `taskexec`.
7. Проверьте пользователей/проекты, ключи, настройки оповещений и типовую задачу.
   Обновите раннеры, переменные Ansible/скриптов и запросы Prometheus.

Сохраните исходные тома и резервную копию до завершения проверки. Для отката остановите
новую службу и восстановите прежние образ, окружение и тома вместе. Не запускайте
две установки с одной базой, доступной на запись.

Старые префиксы окружения не являются алиасами. Пути к базе указываются явно.


## Переход с Semaphore UI

| Было | Стало |
| --- | --- |
| Бинарник, служба, пользователь `semaphore` | `taskexec` |
| Переменные `SEMAPHORE_*` | `TASKEXEC_*` |
| Ansible `semaphore_vars` | `taskexec_vars` |
| `/etc/semaphore`, `/var/lib/semaphore`, `/tmp/semaphore`, `/opt/semaphore` | Соответствующие пути `/…/taskexec` |
| Метрики `semaphore_*` | `taskexec_*` |
| Образы upstream | `impishmd/taskexec` или `ghcr.io/impishmd/taskexec` |
| Go-модуль `github.com/semaphoreui/semaphore` | `github.com/impishMD/taskexec` |

Старый префикс окружения не является алиасом.
Существующие имена БД и абсолютные пути не меняются автоматически; новое имя БД по умолчанию — `taskexec`.

1. Остановите старую службу; сохраните БД, конфигурацию и ключи шифрования.
2. Проверьте восстановленную копию на TaskExec, особенно при переходе с другого upstream-коммита.
3. Обновите окружение, команды службы, пути и монтирования. Для существующей установки
   сохраните диалект/имя БД, ключ шифрования и ключи cookie.
4. Обновите раннеры одновременно с сервером; не смешивайте старые и новые раннеры.
5. Переведите dashboards/alerts на `taskexec_*`; при необходимости обновите клиентов.
6. Проверьте вход, доступ к репозиторию и запуск типовой задачи.

TaskExec применяет миграции базы при запуске. Для отката восстановите резервную копию БД
вместе с соответствующей версией приложения. Проверьте вход клиентов и окружение задач.
