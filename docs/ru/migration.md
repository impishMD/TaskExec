# Миграция с Semaphore UI

[English](../en/migration.md) | **Русский**

v0.0.1 начинает независимую нумерацию JEH. Основа — upstream-коммит
`fc66be94a96cb54c21d28b071382f0cf04554d08`; это не откат исходного проекта на v0.x.

| Было | Стало |
| --- | --- |
| Бинарник, служба, пользователь `semaphore` | `jeh` |
| Переменные `SEMAPHORE_*` | `JEH_*` |
| `/etc/semaphore`, `/var/lib/semaphore`, `/tmp/semaphore`, `/opt/semaphore` | Соответствующие пути `/…/jeh` |
| Метрики `semaphore_*` | `jeh_*` |
| Образы upstream | `impishmd/jeh` или `ghcr.io/impishmd/jeh` |
| Go-модуль `github.com/semaphoreui/semaphore` | `github.com/impishMD/jeh` |

Старый префикс окружения не является алиасом. JSON/YAML-поля, API и SQL-миграции сохранены.
Существующие имена БД и абсолютные пути не меняются автоматически; новое имя БД по умолчанию — `jeh`.

1. Остановите старую службу; сохраните БД, конфигурацию и ключи шифрования.
2. Проверьте восстановленную копию на JEH, особенно при переходе с другого upstream-коммита.
3. Обновите окружение, команды службы, пути и монтирования. Для существующей установки
   сохраните диалект/имя БД, ключ шифрования и ключи cookie.
4. Обновите раннеры одновременно с сервером; не смешивайте старые и новые раннеры.
5. Переведите dashboards/alerts на `jeh_*`; при необходимости обновите клиентов.
6. Проверьте вход, доступ к репозиторию и запуск типовой задачи.

Сам ребрендинг не добавляет SQL-миграций, но при запуске на старой БД могут примениться
унаследованные миграции. Откат — восстановление резервной копии. Изменение имён cookie,
TOTP issuer и переменных задач может потребовать обновления клиентов и аутентификаторов.
