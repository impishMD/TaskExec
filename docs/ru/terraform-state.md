# HTTP-хранилище состояния Terraform / OpenTofu

TaskExec сохраняет состояние рабочих пространств и его историю в основной базе
данных. Backend поддерживает HTTP-клиенты Terraform, OpenTofu и Terragrunt, включая
блокировки. У каждого рабочего пространства своё состояние; все его псевдонимы
используют общую блокировку.

## Задачи в TaskExec

Создайте шаблон Terraform/OpenTofu с рабочим пространством. Включите
**Переопределить backend**, чтобы добавить пустой блок `backend "http"` в рабочую
копию репозитория. По умолчанию используется `backend.tf`, можно выбрать другое
имя с расширением `.tf`. Существующий файл с этим именем заменяется в рабочей
копии задачи. В итоговой конфигурации должен остаться ровно один блок backend.
После выполнения TaskExec удаляет сгенерированный файл.

Адрес backend и адреса LOCK/UNLOCK передаются через переменные окружения задачи.
Каждый запуск получает случайный временный адрес своего рабочего пространства;
после завершения задачи адрес перестаёт работать. Это действует при локальном
запуске и через удалённых исполнителей. В `TASKEXEC_WEB_HOST` укажите URL,
доступный всем исполнителям и контейнерам задач. История сохраняет ID задачи,
записавшей состояние.

Во вкладке **Состояние** шаблона доступны история и постоянные псевдонимы.
Участники проекта видят метаданные истории. Просмотр содержимого состояния и
управление псевдонимами требуют права **Управлять ресурсами проекта** или доступа
администратора сервера. Разрешения только на отдельный шаблон не открывают
состояние общего рабочего пространства.

## Внешние клиенты

1. Создайте общий ключ типа **Логин и пароль** в хранилище ключей проекта.
2. На вкладке **Состояние** добавьте псевдоним и выберите этот ключ.
3. Скопируйте URL и настройте HTTP backend:

```hcl
terraform {
  backend "http" {}
}
```

```sh
export TF_HTTP_ADDRESS='https://taskexec.example.com/api/terraform/ALIAS'
export TF_HTTP_LOCK_ADDRESS="$TF_HTTP_ADDRESS"
export TF_HTTP_UNLOCK_ADDRESS="$TF_HTTP_ADDRESS"
export TF_HTTP_LOCK_METHOD=LOCK
export TF_HTTP_UNLOCK_METHOD=UNLOCK
export TF_HTTP_USERNAME='backend-user'
# Передайте TF_HTTP_PASSWORD через свой менеджер секретов.
terraform init
terraform apply
# Для tofu используются те же параметры.
```

За пределами локальной разработки используйте HTTPS. Передавайте учётные данные
через окружение: параметры backend могут сохраняться в конфигурации и файлах
плана. Выбранный ключ проверяется при каждом запросе, поэтому его смена действует
сразу. Удаление псевдонима отключает его URL, сохраняя историю. Ключ, на который
ссылается псевдоним, нельзя удалить до удаления этой связи.

## Блокировки и история

Реализованы GET, POST, DELETE, LOCK и UNLOCK. Конкурирующая блокировка или запись
с неверным ID блокировки получает HTTP 409 с информацией о текущей блокировке.
Блокировки хранятся в SQL и сохраняются после перезапуска сервера. Если клиент
завершился без снятия блокировки, сначала убедитесь, что он остановлен, затем
выполните `terraform force-unlock LOCK_ID` или `tofu force-unlock LOCK_ID` через
постоянный псевдоним того же рабочего пространства.

Каждая запись создаёт снимок. HTTP DELETE сбрасывает текущее состояние, сохраняя
историю; старый снимок при этом не становится текущим. API проекта позволяет
явно удалить отдельный исторический снимок, когда рабочее пространство не
заблокировано. Это отдельная операция, отличная от сброса backend. Максимальный
размер состояния — 32 МиБ. Аудит содержит операции и ID, без тела состояния и
ключей доступа.

Состояние может содержать пароли и другие секреты. Оно и его история хранятся
в базе как JSON: ограничьте доступ к БД и резервным копиям. Поддерживаются SQLite, PostgreSQL и MySQL.

Описание протокола: [Terraform HTTP backend](https://developer.hashicorp.com/terraform/language/backend/http)
и [OpenTofu HTTP backend](https://opentofu.org/docs/language/settings/backends/http/).
