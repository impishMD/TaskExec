# HTTP API

[English](../en/api.md) | **Русский**

REST API доступен по `/api`, интерактивный Swagger — по `/swagger/` на вашем экземпляре.
Спецификация [api-docs.yml](../../api-docs.yml) включается в каждую сборку интерфейса.

## Аутентификация

Персональные API токены создаются в профиле пользователя и действуют с его правами.
Для сессии используйте `POST /api/auth/login` с JSON
`{"auth":"username","password":"password"}` и полученную cookie.

```sh
curl http://localhost:3000/api/ping
curl -H "Authorization: Bearer $TASKEXEC_API_TOKEN" http://localhost:3000/api/projects
```

Проектные токены — самостоятельные учётные данные для автоматизации в пределах
одного проекта. Они находятся в **Панель управления → Настройки → API токены**.
Просматривать, создавать, перевыпускать и отзывать их могут администраторы сервера
и владельцы проекта. Сведения о создателе сохраняются для аудита: блокировка,
удаление пользователя или исключение из проекта не отключают токен. Он действует
до истечения срока или ручного отзыва. При удалении проекта его токены удаляются.

Секрет показывается только при создании или перевыпуске. В базе хранится его хеш,
а последующие ответы API содержат только сведения о токене. Храните токены в
хранилище секретов CI; не добавляйте их в Git и отчёты об ошибках.

## Права проектного токена

Права задаются явно и не зависят от пользовательских ролей. Выберите конкретные
шаблоны либо разрешите все шаблоны проекта.

| Право | Возможности |
| --- | --- |
| `templates:read` | Названия, типы и описания запрашиваемых переменных разрешённых шаблонов |
| `tasks:run` | Запуск разрешённых шаблонов |
| `tasks:read` | Статусы и основные сведения о запусках разрешённых шаблонов |
| `tasks:logs` | Журналы запусков разрешённых шаблонов; включается отдельно, поскольку журнал может содержать чувствительные данные |
| `tasks:stop` | Остановка только тех задач, которые запущены этим токеном |

Набор «CI» включает чтение шаблонов, запуск и чтение статусов задач. Чтение журналов
по умолчанию выключено. Форма предлагает срок 90 дней; также доступны 30 дней,
год и отсутствие срока действия.

Токен не управляет настройками проекта, ключами доступа, группами переменных,
репозиториями, пользователями, правами или другими токенами. Ему недоступны резервные
копии, чужие проекты, WebSocket, запуск рабочих процессов и подтверждение задач.
Администратором проекта токен не является.

По умолчанию запрос запуска передаёт выбранный шаблон, сообщение и значения
запрашиваемых переменных, объявленных в шаблоне. Отдельно можно разрешить изменение
`git_branch`, `playbook`, `inventory_id`, `arguments`, `environment` и `params`.
Эти параметры способны существенно изменить выполняемую задачу: включайте только
необходимые интеграции поля. Ограничения самого шаблона продолжают действовать;
инвентарь должен принадлежать тому же проекту. `environment` и `secret` передаются
как строки с JSON-объектами. Без разрешения на изменение переменных оба поля
принимают только объявленные в шаблоне переменные с проверкой типа, вариантов
выбора и обязательности. Для пропущенных переменных используются сохранённые
значения по умолчанию. Переменные типа «Секрет» сохраняются через механизм секретов
задачи, даже если клиент передал их в `environment`.

## Запросы к API проекта

Проектный токен передаётся в обычном заголовке Bearer. Под
`/api/project/{project_id}` разрешены следующие пути:

| Метод | Путь | Право |
| --- | --- | --- |
| GET | `/templates`, `/templates/{id}` | `templates:read` |
| POST | `/tasks` | `tasks:run` |
| GET | `/tasks`, `/tasks/last`, `/templates/{id}/tasks`, `/tasks/{id}` | `tasks:read` |
| GET | `/tasks/{id}/output` | `tasks:logs` |
| POST | `/tasks/{id}/stop` | `tasks:stop` |

Список задач возвращает до 100 записей, сначала новые. Для следующей страницы
передайте `?before={last_id}`. Ответ о задаче содержит только идентификаторы задачи,
проекта и шаблона, статус, временные отметки, версию и ID/название запустившего токена.
Ответ о шаблоне не содержит учётных данных, значений переменных и значений по
умолчанию. При запуске укажите ровно одно поле: `template_id` или `template_name`.
Неизвестные поля запроса отклоняются. Для остановки передайте JSON `{}` или
`{"force":true}`.

```sh
curl -H "Authorization: Bearer $TASKEXEC_PROJECT_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"template_id":42,"message":"CI deployment"}' \
  https://taskexec.example.com/api/project/1/tasks
```

Для управления токенами нужна сессия или персональный токен администратора сервера
либо владельца проекта:

- `GET /api/project/{project_id}/tokens` — список, включая срок и время последнего использования.
- `POST /api/project/{project_id}/tokens` — выдача: `name`, `scopes`, `template_ids`
  (либо `all_templates: true`), необязательные `overrides` и `expires_at` в формате RFC 3339.
- `DELETE /api/project/{project_id}/tokens/{token_id}` — ручной отзыв с сохранением истории.
- `POST /api/project/{project_id}/tokens/{token_id}/rotate` — перевыпуск с теми же
  полями, что при создании, и атомарным отзывом предыдущего токена.

После перевыпуска старый токен сразу перестаёт работать. Задачи в очереди повторно
проверяются перед выполнением и не стартуют с отозванным или просроченным токеном.
Уже выполняющиеся задачи продолжают работу. Новый токен получает собственный ID
и не может остановить запуски предыдущего: для этого используйте учётную запись
пользователя.

Выдача, перевыпуск, отзыв и действия с задачами фиксируются в аудите.
В истории задач указан запустивший их токен.
